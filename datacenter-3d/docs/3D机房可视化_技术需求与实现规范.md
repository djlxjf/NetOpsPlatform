## 2. 3D 模块技术需求分解（五大维度）

### 2.1 模型结构规范（节点层级 / 网格拓扑 / 建模精度）

**2.1.1 节点层级组织（R-01，大纲 §5.1.1）**
- 层级契约：`Scene → RoomGroup(按 room_id) → Zone/Row(冷/热通道分区，可选) → CabinetGroup(单柜) → DeviceMesh(设备) / CabinetShell(柜体) / LoadBand(负载色带)`。
- 全局索引：维护 `Map<sn, Object3D>`，收到 WebSocket 帧时 **O(1)** 定位网格；**禁止遍历场景树**查找。
- 拾取白名单：装饰模型（无 `sn`）标记 `userData.pickable = false`，不参与射线拾取，不进入索引表。
- 图表与 3D 解耦：ECharts 挂在 DOM 面板，3D canvas 全屏；二者仅通过 Pinia `sceneStore.currentSn` 共享选中态，互不操作 DOM（大纲 §5.1.8）。

**2.1.2 网格拓扑结构（R-02 / R-12，大纲 §2.4 + 3D 建模通用规范）**
- 机柜柜体：单一母版低模（建议 0.5k–2k 三角面/柜），42U 空柜统一母版，仅平移 / 旋转 / 换贴图，不重复建几何体。
- 设备：同型号使用 `InstancedMesh`，单抽屉式网格批量绘制（大纲 §5.1.2）。
- 拓扑纪律：以**四边形面**为主；沿机柜棱线布置**边缘循环（edge loops）**；**极点（pole）**置于背面 / 底面不可见区域；禁止 N-gon；UV 接缝置于背面 / 底部。
- 面数预算：单机房总面数 **≤150 万三角面**（大纲 §2.4 硬指标）；200 柜场景单柜均值 ≤3k 三角面（约 60 万，预留余量给设备与装饰）。

**2.1.3 建模精度（R-12，大纲 §4.3.2 `rackPos`）**
- 世界单位：**米（m）**；标准机柜外形 0.6m(宽) × 1.2m(深) × 2.0m(高)（42U）。
- 尺寸误差：母版建模与实测尺寸偏差 **≤ ±1cm**（派生，待评审）。
- 坐标映射：`rackPos{x, y, z, rotateY}` 为归一化坐标，前端据此把母版摆到 GLB 对应位置，避免手工对齐；坐标精度 **小数点后 2 位（1cm）**。
- U 位精度：1U = 44.45mm；设备 `uHeight` 取整 U；槽位对齐误差 **≤ ±0.5U**（派生，待评审）。

### 2.2 材质与 PBR 规范（R-08，大纲 §2.4）

**2.2.1 PBR 工作流**
- 采用 **Metallic-Roughness** 双工作流（glTF 2.0 标准），不引入 Specular-Glossiness 双套。
- 材质简化：金属度 / 粗糙度两张贴图即可表达绝大多数机柜设备（大纲 §2.4 明确"简化"）。
- 禁止外部嵌入 HDR 视频（大纲 §2.4）；环境反射可用**低分辨率烘焙环境贴图**，不走运行时 HDR 视频流。

**2.2.2 贴图规格（派生，待评审）**
- 机柜 / 设备母版：基础套 **2K（2048²）** = Albedo + Normal + Roughness + Metallic；重点设备可选 **4K**。
- 压缩格式：优先 **KTX2（Basis）** 或 PNG（带透明）；禁用未压缩 TGA 大图。
- UV：语义分岛（金属 / 玻璃 / 塑料分色），重叠 UV 仅用于对称部件；texel density 建议 **256–512 px/m**。

**2.2.3 物理属性参数（派生，待评审，基于 PBR 通用取值）**
| 材质 | metallic | roughness | 备注 |
| --- | --- | --- | --- |
| 机柜金属外壳 | 0.8–1.0 | 0.3–0.5 | 喷塑金属 |
| 服务器前面板（塑料/喷漆） | 0.0–0.2 | 0.6–0.8 | 哑光 |
| 玻璃 / 指示灯 | — | — | 单独 `emissive`（告警脉冲）或 transmission（可选） |
| 地面 / 墙体 | 0.0–0.1 | 0.7–0.9 | 哑光，靠 AO/接触阴影 |

### 2.3 光影与渲染规范（R-09，大纲 §5.1 + 引擎已验证参数）

**2.3.1 光照方案**
- 基础三光（已在 `datacenter-3d/src/scene.js` 验证）：
  - `HemisphereLight(sky 0x88aaff / ground 0x0a0e16, 0.55)`
  - `DirectionalLight(0xbfe3ff, 0.7, position 20/40/18)`
  - `AmbientLight(0x223044, 0.4)`
- 可选增强：低分辨率环境贴图提升金属反射，不引入 HDR 视频。

**2.3.2 阴影质量分级（派生，待评审）**
| 档位 | 条件 | 参数 | GPU 开销 |
| --- | --- | --- | --- |
| 低（降级） | 帧率连续 3s < 40 | 关闭实时阴影，仅 AO / 接触阴影 | ≈0 |
| 中（默认） | 常态 | `PCFSoftShadowMap`，mapSize 1024，单级 | 中 |
| 高（旗舰） | FPS ≥ 55 自动启用 | mapSize 2048，软阴影半径更大 | 高 |
- 自动升降档策略与大纲 §5.1.6 / §6.1 降级链路一致：关脉冲 → 关标签 → 切 2D 看板。

**2.3.3 后期处理标准**
- 泛光 Bloom：`UnrealBloomPass(strength 0.62, radius 0.7, threshold 0.85)`（已在 scene.js 验证）。
- 告警脉冲：`emissive` 系数随 `sin` 周期变化，**循环结束自动停止**，避免永久动画常驻吃 GPU（大纲 §5.1.3）。
- 色调映射：`ACESFilmicToneMapping`，`exposure 1.1`（已验证）。
- 雾：`FogExp2(0x05070d, 0.011)`（已验证）；多机房大场景密度可调。

### 2.4 交互设计规范（R-03 / R-04 / R-05 / R-07，大纲 §4.2 / §5.1）

**2.4.1 视角控制（R-04）**
- 轨道相机 `OrbitControls`：`enableDamping`，`dampingFactor = 0.08`，`maxPolarAngle = π×0.495`（不穿地），`minDistance 4`，`maxDistance 130`（已在 scene.js 验证）。
- 定位飞行：自研补间（60 帧线性插值 + easeInOut），从当前位姿滑到目标机柜；不引入重型 tween 引擎（大纲 §5.1.4）。
- 巡检路径：预设坐标点数组沿时间插值（第一人称 / 轨道可选）。

**2.4.2 操作反馈（R-03 / R-07）**
- 拾取：`Raycaster` **节流**，仅 `pointerdown` 触发，`move` 不拾取（大纲 §5.1.5）。
- Hover：tooltip 显示 `sn / 类型 / 状态`；默认关闭机柜名标签，仅 hover / 告警时显示（大纲 §5.1.7）。
- 选中：抽屉 / 详情面板展示资产详情 + 近 24h 曲线（查 VM 降采样）。
- 告警脉冲：紧急告警红 + `emissive` sin 脉冲，右上角列表插入一条，点击飞行定位（大纲 §4.2.3）。
- 断网降级：WS 断开 >10s → 显示"数据中断，展示为最后缓存"，颜色冻结在 Redis 快照值（大纲 §4.2.5）。

**2.4.3 事件触发逻辑（对应大纲 §4.1 / §4.2）**
| 触发源 | 事件 | 处理逻辑 |
| --- | --- | --- |
| 用户 | `pointerdown` | raycast → `mesh.userData.sn` → 查 `Map` → 开抽屉 |
| 后端 | WS `metric` 帧 | 按 `sn` 更新对应网格颜色 / 标签；**500ms 合并缓冲**，避免每帧重绘（大纲 §5.1.6） |
| 后端 | WS `alert` 帧 | 网格变红脉冲 + 列表插入 + 可选相机飞行（大纲 §4.2.3） |
| 用户 | 点击摄像头热点 | 后端代理取流（ONVIF / SDK）→ 前端弹窗 flv/HLS，不直连（大纲 §4.2.4） |

### 2.5 性能优化规范（R-06 / R-10 / R-11，大纲 §5.1.6 / §6.1）

**2.5.1 LOD 分级策略（R-11，派生，待评审）**
| 档位 | 距离阈值 | 渲染内容 |
| --- | --- | --- |
| LOD0（近） | < 8m | 全细节（母版 + 贴图 + 设备 Mesh） |
| LOD1（中） | 8–20m | 合并简化几何，设备用代理盒（InstancedMesh） |
| LOD2（远） | > 20m | 仅柜体盒 + 色带，无设备细节；标签阈值 15m（大纲 §5.1.7） |
- 切换依据：相机距离 + 视锥剔除，在帧预算内合并切换；阈值可随场景规模配置。

**2.5.2 Draw Call 优化（R-02 / R-06）**
- 同型号设备 `InstancedMesh` 批量；单机房 draw call **目标 ≤250**（大纲 §5.1.2 硬指标）。
- 地面 / 墙体 / 管线合并为少量 static mesh；相同 `material` 共用以合批。
- 禁止每设备独立 draw call。

**2.5.3 内存管理（R-10）**
- 资源预算：首屏 GLB 解压后 **≤15MB**（大纲 §5.1.6）。
- 模型分片：按机房加载；切换机房 **dispose 旧场景** `geometry.dispose()` + `material.dispose()` + 纹理释放，防内存泄漏（大纲 §5.1.6）。
- 传输优化：Draco 压缩 + KTX2 贴图；静态资源 Nginx gzip / 缓存头（大纲 §6.1）。
- 快照降级：Redis `snap:{sn}`（TTL 30min）首屏 `HMGET` 批量补齐，再由增量帧覆盖（大纲 §5.2.5）。

## 5. 可验证事实与个人推测的区分

**可验证事实（直接源自大纲原文，可溯源至 § 标注）**
- 引擎 / 前端 / 资源格式选型（§2.1 / §2.4）。
- 核心性能指标数值：60 FPS（机柜 ≤200）、首屏 ≤8s、端到端 ≤3s（§0 / §6.1）。
- 面数预算 150 万、draw call ≤250、GLB ≤15MB（§2.4 / §5.1.2 / §5.1.6）。
- 着色规则：正常本色 / 离线灰 50% 透明 / 一般告警黄 / 紧急告警红 + 自发光脉冲（§5.1.3）。
- 相机阻尼 0.08、maxPolarAngle 限制、min/maxDistance（§5.1.4，且已在 `scene.js` 验证）。
- 拾取节流、标签距离阈值 15m、WS 500ms 合并、断网 >10s 冻结（§5.1.5 / §5.1.6 / §5.1.7 / §4.2.5）。
- `rackPos{x,y,z,rotateY}` 归一化坐标模型（§4.3.2）。

**个人推测 / 设计扩展（由 3D 建模专业标准派生，不在大纲范围内，需评审确认）**
- 阴影三档（低/中/高）的 mapSize（1024 / 2048）与启用条件。
- 贴图 2K / 4K 规格、KTX2 压缩、texel density（256–512 px/m）。
- PBR 物理属性数值区间（金属外壳 metallic 0.8–1.0 等）。
- LOD 三档距离阈值（8m / 20m / 15m 标签阈）。
- 建模精度量化值：尺寸偏差 ≤±1cm、U 位对齐 ≤±0.5U、模型加载耗时 ≤2s。
- 以上派生项已在该规范中以"派生，待评审"明确标注，未作为大纲既成结论使用。

## 6. 与现有 `datacenter-3d` 原型的关系（补充）

当前 `datacenter-3d` 工具（四阶段规划流程：平面绘制 → 门窗布置 → 3D 预览 → 设备摆放）是大纲 M0/M1 级别的**规划态原型**，已验证与本规范一致的部分参数：`OrbitControls` 阻尼 0.08、ACESFilmic 曝光 1.1、`FogExp2` 0.011、`UnrealBloomPass(0.62,0.7,0.85)`、`maxPolarAngle π×0.495`。但现有原型为**程序化几何体**（非 GLB 母版），未实现 R-02 实例化母版、R-08 PBR 贴图、R-11 LOD 分级，需在 M1–M5 阶段补足。
