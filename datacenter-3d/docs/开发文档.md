## 一、需求背景与目标

### 1.1 背景

用户需要一个**纯前端、零后端**的三维机房 / 设备间布局规划工具，用于在无真实设备的情况下完成机房空间规划、门窗布置与设备摆放的数字化推演。工具需兼顾「规划直观性」与「渲染流畅性」，并以深色科技风呈现。

### 1.2 核心目标

- 以 3D 形式呈现机房整体空间结构（地面、墙体、门窗洞口、顶部管线）。
- 支持机柜按「一排 / 两排（冷热通道）」成列排布，并支持单台设备的添加、删除、移动、旋转。
- 相机支持轨道旋转 / 缩放 / 平移，并提供俯视、全景等预设机位。
- 支持鼠标悬停高亮、点击选中、编号搜索定位机柜。
- 提供机柜密度、温度、状态、类型等多维可视化着色开关。
- 深色科技风格（网格地面、发光描边、泛光后处理、ACES 色调映射）。
- 保证渲染性能流畅（实例化渲染、FPS 自适应降级）。
- 提供可直接运行的完整实现代码与技术方案说明。

### 1.3 工作流目标（四阶段）

工具按四阶段组织工作流，阶段间实时联动：

1. **① 平面绘制**：调整机房长 / 宽 / 高，墙体与地面实时重建。
2. **② 门窗布置**：在立面编辑器中添加 / 移动 / 缩放门窗，或直接点击 3D 墙面切换编辑对象。
3. **③ 3D 预览**：自由旋转 / 缩放 / 平移查看整体效果。
4. **④ 设备摆放**：添加设备、拖动调整、批量成列、进入机柜 3D 详情。

### 1.4 关键约束与默认策略（来自用户修改要求）

- 首次进入应为**空机房**（仅有平面与墙体，不带任何设备）。
- 默认墙体**不含任何门窗**，由用户在阶段②自行布置。
- 完成摆放后可**锁定布局**，锁定后设备与墙面均不可移动；点击机柜门板可开合，开合角度 **100°** 且不能与相邻机柜重叠。
- 机房墙体四角应**封闭无缺口**。
- 点击机柜进入详情 / 开合门板的交互需**顺畅**（避免逐面递归射线导致的卡顿）。

## 四、关键实现逻辑说明

### 4.1 四阶段流程与状态机

- `main.js` 中 `setStage(n)` 控制四个阶段的显隐与相机机位：
  - 阶段①俯视（`CameraDirector.top()`）；阶段②打开立面面板并 `switchWall`；阶段③全景（`panorama()`）；阶段④显示设备工具栏。
  - 每次切换均调用 `persistIfValid()` 自动写入 localStorage。
- 阶段切换时若处于机柜详情视图，会先 `detail.hide()` 退出。

### 4.2 机房重建与墙体四角处理（M8）

`room.js` 的 `buildWallMesh(wall, key, dims)`：

- 墙体使用 `THREE.Shape` 矩形 + 门窗 `holes`（`THREE.Path`） → `ExtrudeGeometry` 拉伸出真实洞口。
- **四角补齐逻辑**：`back` / `front` 墙在长度方向各向两端延伸一个墙厚（`ext = wall.thickness`），左右墙则嵌在前后墙之间，从而避免转角出现 0.3×0.3m 的缺口，且无重叠。
- 墙体 mesh 标记 `userData.wallKey`，供阶段②在 3D 中点击墙面切换编辑对象。

### 4.3 顶部管线自适应（修复游离线条）

`room.js` 根据房间尺寸动态计算管线数量与内布位置（非写死偏移）：

```js
const pipeXCount = Math.max(1, Math.min(4, Math.floor(dims.depth / 8)));
const pipeZCount = Math.max(1, Math.min(3, Math.floor(dims.width / 10)));
// 位置：((i+1) * 长度) / (count + 1) 等距内布
```

房间缩小后管线始终分布在房间内部，不再越界游离。

### 4.4 设备规格与机柜模型

- `config.js` 定义五类设备占地尺寸：`server(0.6×2.0×1.0)`、`ac(1.4×2.2×1.2)`、`power(0.8×2.2×1.0)`、`ups(0.9×2.0×1.0)`、`fire(0.3×0.9×0.3)`。
- **机柜模型**：`rackModel.js` 移植自 `cockpit-rack-3d-model.html`。原始建模单位为 1 单位 = 10mm，整体缩放 `0.01` 转米制。标准 19" 42U 机柜外廓 600×1000×1995mm，柜内 `DEVICES` 数组含 20 台设备（U 位 / 端口数与源文件一致）。
- **双轨渲染**：`racks.js` 的 `MODEL_BUILDERS = { server: buildCabinetModel, fire: buildExtinguisherModel }` 走「克隆共享 Group」；其余类型（ac / power / ups）走 `InstancedMesh`。

### 4.5 不可见代理盒拾取（M10，解决卡顿）

精细模型逐面递归射线代价高，`racks.js` 采用廉价代理盒：

- 每台设备生成一个共享 `1×1×1` 几何、按类型缩放、`visible:false` 的代理 `Mesh`，存入 `proxies`（`racks.js` 第 142–151 行）。
- `bodies()` 只返回代理盒；`fromIntersection()` 经 `userData.rackId` 反查设备对象。
- 命中代理盒后，若为服务器机柜，再对门枢轴 `[rack._frontPivot, rack._rearPivot]` 做一次精确二次拾取，区分「点在门体 → 开合」与「点在柜体 → 进详情」。

### 4.6 门板开合 100° 与相邻碰撞（M7）

- `racks.js` 常量 `DOOR_ANGLE = 1.745`（即 100°）。
- `_doorAABB(rack, which)` 计算门板完全打开后的世界包围盒（铰链 → 门板末端两点，含机柜自身旋转）。
- `_doorBlocked(rack, which)` 以 `TOL=0.05` 容差判断该包围盒是否与其他设备半占距相交；若受阻，`toggleDoor()` 返回 `{ ok:false }` 拒绝开合。
- 逐帧 `update(dt)` 用 lerp 趋向目标角，实现平滑动画。

### 4.7 批量成列与冷热通道（需求 2）

`racks.js` `addBatch(kind, p, dims)`：

- 单排（`col1`）：沿 Z 方向以 `gap=0.72m`（0.6 宽 + 0.12 间隙）成列放置，机柜面朝 +X。
- 双排（`col2`）：第二排在 `x2 = p.x + 2.3`（柜深 1.0 + 通道 1.3）处面朝 -X，**相对而立形成 1.3m 冷热通道**。
- 自动避开房间边界与已有设备（`_overlapsAny` 校验，容差 0.05m）。

### 4.8 锁定机制（M7）

- `main.js` 维护 `locked` 标志并持久化到 v3（`savePlan({...}, ..., locked)`）。
- `syncLockUI()` 统一禁用：尺寸输入框（`dimW/dimD/dimH`）、设备工具栏按钮、门窗添加 / 删除按钮，并设置 `editor.locked = true` 禁止立面编辑拖拽。
- 锁定后仍允许：点击机柜门板开合、进入机柜 3D 详情（阅读 / 查看用途，不改变布局）。

### 4.9 默认空门窗与空机房（M1 / M9）

- `wallLayout.js` `defaultWallLayout()` 返回四面墙且 `openings: []`（封闭空机房）。
- `main.js` 启动时 `racks.loadFrom(saved?.racks || [])`：只有本地存档才含设备，首次进入为纯平面。
- 「重置」按钮调用 `racks.clearAll()` + `defaultWallLayout()`，恢复默认空机房（**注意：本地旧存档需点「重置」才会清空演示数据**）。

### 4.10 着色模式与状态色条

- `racks.js` `colorMode` 支持 `status` / `temperature` / `density` / `type`：
  - 实例化类型经 `setColorAt(i, _colorFor(rack))` 逐实例着色；热力用 `config.js` 的 `heat(t)`（蓝→青→绿→黄→红）。
  - 精细模型（机柜 / 灭火器）通过顶部 `rack._statusMat` 状态色条呈现当前着色。

### 4.11 性能策略（需求 8）

- `scene.js` 每 500ms 统计 FPS；若连续两周期 `<40` 帧，触发 `_adaptive()`：**关闭泛光**（`setBloom(false)`）+ **像素比降为 1**。
- 实例化渲染降低 draw call；仅 3 盏灯、无阴影；几何体复用 + 窗口尺寸变化自适应重建。

### 4.12 持久化与导入导出

- `wallLayout.js` `savePlan` / `loadPlan` 使用 localStorage 键 `dc3d.plan.v3`，结构 `{ v:3, dims, walls, racks, locked }`。
- `main.js` 提供「导出 / 导入 JSON」（兼容 v2 纯墙面格式），支持备份迁移；「保存」仅在布局合法时启用。

### 4.13 指针交互（拖动 vs 点击）

`main.js` 统一 `pointerdown / pointermove / pointerup`：

- `pointerdown`：阶段①判定房间边缘拖拽；阶段④判定设备拖拽（记录抓取偏移并暂停 OrbitControls）。
- `pointerup`：以 `moved < 5px` 判定为点击；若拖拽位移极小仍走点击逻辑（修复「按住即拖拽」导致点击失效的问题），从而实现门板开合 / 进入详情 / 墙面点选 / 批量落位。

## 六、快速启动

```bash
# 方式 A：零安装（需联网，CDN 加载 three）
python -m http.server 8080
# 浏览器访问 http://localhost:8080

# 方式 B：Vite（离线推荐）
npm install && npm run dev     # http://localhost:5173
```

> 操作要点：顶部 ①②③④ 切换阶段；①拖动房间边缘或输入长宽高；②立面编辑器拖拽门窗；④工具栏添加设备、拖动移动、`R` 旋转、`Del` 删除、点击机柜进入 3D 详情；全局支持编号搜索、四种着色、泛光开关与 FPS 实时显示。
