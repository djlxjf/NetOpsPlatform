## 2. 期间发现并修复的 2 个集成缺陷

### 2.1 vite manualChunks 误匹配 `.vue` 扩展名（影响全应用代码分割）

- 现象：构建产物中全部视图组件与 three.js 被打入首屏 `vue-vendor` 分块（2.2MB），各路由的懒加载 `import()` 未产生独立分块；机房规划模块连同 three.js 进入首屏加载路径。
- 根因：`vite.config.js` 的 `manualChunks` 函数使用 `id.includes('vue')` 判断 Vue 生态包，该子串同时命中 `src` 下所有 `.vue` 文件的扩展名。
- 修复：改为 node_modules 路径边界正则（`/[\\/]node_modules[\\/](vue|vue-router|pinia)[\\/]/` 等三式并列）。
- 修复后核查：每个路由视图生成独立分块；three.js 核心（603KB，含 OrbitControls）仅在访问 `/datacenter` 时按需加载；`vue-vendor` 不再含任何应用视图代码。

### 2.2 Shadow DOM 元素查找失效（导致工具初始化崩溃）

- 现象：Vue 嵌入模式下工具初始化抛出 `TypeError: Cannot read properties of null (reading 'querySelectorAll')`，three.js 场景无法建立。
- 根因：`datacenter-3d/src/main.js` 的元素查找使用 `rootEl.querySelector`，而宿主元素的 querySelector **不会进入 shadowRoot**——Vue 集成时全部工具标记（#stepper、#detail-bar 等）均挂载于 shadowRoot 内，查找全部返回 null。
- 修复：`_createApp` 增加 domRoot 解析（`rootEl.shadowRoot` 含 `#app` 时以 shadowRoot 为查找根，否则退回 rootEl，独立运行模式行为不变）；`UIController` 增加 `rectRoot` 参数，tooltip 视口坐标改以宿主元素矩形换算（shadowRoot 无 `getBoundingClientRect`）。
- 修复后核查：上述 18 项断言全通过，控制台零错误。
